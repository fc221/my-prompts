## 是什么

服务端怎么接收、校验、存放和分发用户上传的文件：文件本体放对象存储，数据库只存元数据；客户端拿预签名地址直传，下载用带过期时间的签名链接。对外的上传下载接口怎么设计看「文件上传与下载」。

## 适合

报销单的发票附件、工单截图、会员头像、商品图片、批量导入用的 Excel。

## 不适合

结构化数据直接进数据库，不存成文件；生成 PDF 见 PDF 领域的条目；超大文件分片上传的协议细节以所用对象存储的文档为准。

## 注意

最常见的错误是信任用户给的文件名和类型：文件名带 ../ 可以穿越目录；扩展名是 .jpg 的文件可能是 HTML 或脚本，在主站同域下打开就会执行。存储路径由服务端生成，类型按文件内容判断，下载走独立域名或强制下载。

## 要点

- 存放：文件放 S3 兼容的对象存储，存储桶默认私有；应用服务器本地磁盘只做临时中转（多实例和容器重启会丢）；元数据表存 file_id、object_key、原始文件名、size、mime、sha256、owner_id、tenant_id、biz_type、status、created_at。
- 对象键：服务端生成，按 租户/业务/年/月/随机 ID.扩展名 组织，如 t1024/expense/2026/10/01JBK7Q9ZQ3V.pdf；原始文件名只存在元数据里，下载时作为展示名。
- 直传：客户端先向服务端申请，服务端校验权限和业务限制后返回预签名 URL（有效 5–15 分钟），限定 Content-Type 和大小范围（POST Policy 的 content-length-range）；上传完成后客户端通知服务端，服务端确认对象存在、大小一致，再把 status 从 pending 改为 active。
- 校验：扩展名白名单加文件头魔数双重校验（发票只收 PDF、JPG、PNG）；大小按业务定（头像 2MB、发票 10MB）；图片在服务端重新编码或经图片处理服务生成缩略图，顺带去掉 EXIF 里的定位；SVG 和 HTML 不按图片接收。
- 下载：私有文件发签名 URL（有效 5–10 分钟），签发前校验当前用户对这张业务单据的权限；响应头 Content-Disposition 设为 attachment，中文文件名用 filename* 的 UTF-8 编码写法；用户文件放在独立域名，不和主站同源。
- 扫描：上传后异步做病毒扫描，通过前只有上传者本人可见；Excel 导入放到后台任务里解析，限制行数和单元格数。
- 清理：status 为 pending 超过 24 小时的对象和记录由定时任务清除；业务单据删除后附件按保留期处理；存储桶配置生命周期规则，半年没访问的附件转低频存储。
- 去重和配额：按 sha256 识别重复上传，复用已有对象；按租户或用户统计用量，超出配额时拒绝签发上传地址。

## 提示词

检查并改造{项目}的文件上传，涉及{业务，如报销发票附件、工单截图}，对象存储用{对象存储服务}。
1. 盘点：找出上传和下载的全部代码路径，记录文件存在哪里、路径怎么生成、校验了什么（扩展名、内容、大小）、下载怎么鉴权、有没有元数据表和清理机制；标出用用户文件名做路径、只校验扩展名、存储桶公开读、大文件经应用服务器中转的地方。
2. 按规则改：存储桶改私有；建或补齐文件元数据表；对象键由服务端生成；改为预签名直传加上传确认（pending 到 active）；扩展名白名单加魔数校验和大小上限；图片重新编码并去掉 EXIF；下载前校验业务权限，签发 5–10 分钟的签名 URL 并强制附件下载；pending 超过 24 小时的由定时任务清理。
3. 补测试：改了扩展名的伪造文件被拒绝；无权限用户拿不到下载地址；签名过期后无法访问。
4. 汇报：改动文件、存量文件的迁移和处理方式、测试结果。
