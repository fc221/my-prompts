## 是什么

把随环境变化的配置（数据库地址、超时、开关）和不能泄露的密钥（数据库密码、支付私钥、AppSecret）从代码里分出来：配置按环境注入，密钥放进专门的密钥管理，代码仓库里没有一个真实密钥。

## 适合

新项目搭配置体系；仓库里发现明文密码要清理；开发、测试、预发、生产的配置混在一起；密钥要定期轮换；手机号、身份证号要加密存储。

## 不适合

运行时按用户、按比例开关功能用功能开关平台，和启动配置分开管；对外 API Key 的签发看「认证方式」。

## 注意

密钥一旦提交进 Git，删掉文件也还留在历史里。正确做法是立刻作废并轮换这个密钥，再清理历史。另一个常见泄露是启动时把全部配置打印到日志。

## 要点

- 来源和优先级：代码里的安全默认值，低于按环境的配置文件，低于环境变量，低于密钥管理服务；启动时一次性加载成类型化的配置对象（Spring @ConfigurationProperties、pydantic-settings、Go 结构体加 envconfig），业务代码只读这个对象。
- 启动校验：必填项缺失或格式不对（URL、端口、时长）时启动失败，并指出是哪一项；生产环境检测到开发默认值（如默认的 JWT 签名密钥）直接退出。
- 密钥存放：生产密钥放在 KMS、Vault 或云厂商的密钥管理服务，运行时凭服务身份读取；Kubernetes Secret 默认只是 base64 编码，要开启 etcd 静态加密并收紧读取权限。
- 仓库卫生：.env 写进 .gitignore，只提交 .env.example（列出全部键名和示例值）；CI 跑密钥扫描（gitleaks、trufflehog），发现即阻止合并。
- 最小权限：每个服务独立的数据库账号；应用账号只有增删改查权限，迁移用单独的带 DDL 权限的账号；第三方密钥按环境分开，测试环境用测试密钥。
- 轮换：密钥带版本号或 kid，代码在过渡期同时接受新旧两个版本（如 JWT 验签同时认新旧公钥），切换完成后撤销旧的；轮换步骤写成手册，每年至少演练一次。
- 字段加密：手机号、身份证号、银行卡号用 AES-256-GCM 加密存储，数据密钥再由 KMS 主密钥加密（信封加密）；要按手机号查询时另存一列 HMAC-SHA256 盲索引；展示时掩码。
- 防泄露：配置对象的 toString 和日志输出对密钥字段打码；错误信息和健康检查不带连接串；前端构建产物里没有任何服务端密钥。

## 提示词

整理{项目}的配置和密钥管理，部署在{Kubernetes / 云主机 / 其他}，密钥管理用{KMS / Vault / 云厂商密钥服务 / 暂无}。
1. 盘点：扫描仓库和 Git 历史里的明文密码、令牌、私钥；列出所有配置项的来源（代码、配置文件、环境变量）、读取位置和是否必填；标出业务代码直接读环境变量、启动时打印配置、多个服务共用数据库账号的地方；确认{敏感字段，如手机号、身份证号}怎么存。
2. 按规则改：配置集中加载成类型化对象并在启动时校验，缺失即失败；密钥移入密钥管理服务，仓库只留 .env.example；CI 加密钥扫描；应用账号和迁移账号分开；密钥支持新旧版本并存；敏感字段用 AES-256-GCM 信封加密加盲索引；日志和错误信息里的密钥打码。
3. 已泄露的密钥列出清单并给出轮换步骤，只删文件不算处理完。
4. 汇报：配置项清单、改动文件、需要人工轮换的密钥、验证方式（缺配置时启动失败、密钥扫描通过）。
