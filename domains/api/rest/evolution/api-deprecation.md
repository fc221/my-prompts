## 是什么

旧版本或旧 API 从“还能用但别再接”到彻底关闭的流程：在文档和响应头里标记弃用，给出下线日期和迁移说明，按调用量逐个跟进，到期返回 410。

## 适合

新版本发布后处理旧版本；删除已经没人用的 API；字段改名后清理旧字段。

## 不适合

还在决定要不要升版本看「版本管理」；判断一次改动是否兼容看「向后兼容规则」。

## 注意

只在文档里写一句“已废弃”几乎没人看到。要在响应头里标记，按调用方统计流量，点对点通知还在调用的人；正式关闭前先短时关闭演练一次，比到期直接关安全。

## 要点

- Deprecation 头（RFC 9745）写弃用时间，格式是 @ 加 Unix 秒数：Deprecation: @1782835200（2026-07-01 00:00 北京时间）；时间可以在将来，表示到点开始弃用。
- Sunset 头（RFC 8594）写关闭时间，用 HTTP 日期格式：Sunset: Thu, 31 Dec 2026 16:00:00 GMT；关闭时间不早于弃用时间。
- 同时用 Link 头指向迁移文档：Link: </docs/migrate-v2>; rel="deprecation"; type="text/html"。
- 从宣布弃用到关闭至少 6 个月，对外开放平台 12 个月；期间只修安全问题和严重缺陷。
- 按调用方（应用 ID、AppKey、客户端版本）统计旧 API 调用量，每月通知仍在调用的调用方，关闭前 30 天和 7 天各再提醒一次。
- 关闭前在低峰期做 1 小时的限时关闭，返回 410，让没留意通知的调用方提前暴露出来。
- 关闭后返回 410 Gone，错误体里给迁移文档地址；410 响应至少保留 3 个月再删路由。
- OpenAPI 里给弃用的 API、参数和字段标 deprecated: true，description 里写替代方案。

## 提示词

计划下线{服务名}的 {要下线的接口或版本}，替代方案是 {替代接口}。先读路由、网关配置、调用日志和接口文档。
1. 统计近 30 天调用量，按调用方（应用 ID、客户端版本）列出清单。
2. 给这些接口的响应加三个头：Deprecation（@ 加 Unix 秒数，弃用开始时间）、Sunset（HTTP 日期格式，关闭时间 {关闭日期}）、Link 指向迁移文档并带 rel="deprecation"。
3. OpenAPI 里标 deprecated: true，写清替代接口和字段对照。
4. 写一份迁移文档：新旧请求和响应对照、示例、常见问题。
5. 给出通知计划：宣布、每月跟进、关闭前 30 天和 7 天提醒、一次 1 小时的限时关闭演练。
6. 到期后接口返回 410 和迁移文档地址，保留 3 个月再删代码。
最后列出改动文件和时间表。
