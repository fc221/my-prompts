## 是什么

GET、POST、PUT、PATCH、DELETE 各管一类操作；哪些方法安全（不改状态）、哪些幂等（同一请求发多次和发一次效果相同）是 HTTP 语义定好的。网关重试、浏览器预取、客户端超时重发都依赖这套语义，方法用错就会重复下单或误删数据。

## 适合

给每个 API 定方法；排查“超时重试导致重复扣款、重复建单”；网关或请求层要决定哪些请求可以自动重试。

## 不适合

POST 创建也要能安全重试看「幂等键」；部分更新的请求体格式看「部分更新」；一次处理多条看「批量操作」。

## 注意

幂等说的是服务端状态，不是响应相同：第二次 DELETE /orders/:id 可以返回 404，但不能再回滚一次库存。GET 必须没有副作用，用 GET 去“标记已读”“发验证码”，会被预取、爬虫和缓存反复触发。

## 要点

- GET：读取，安全且幂等，可缓存；条件全部放查询参数，不带请求体。
- POST：创建或触发动作，不幂等；创建成功返回 201 和 Location；需要可重试时加 Idempotency-Key，见「幂等键」。
- PUT：整体替换，幂等；请求体是完整资源，没传的字段按默认值处理；客户端自定 ID 时可以用 PUT /resources/:id 做创建或替换，首次创建返回 201，之后返回 200。
- PATCH：部分更新，规范上不保证幂等；用 JSON Merge Patch 设置字段值时实际幂等，“库存减 1”这类增量操作不幂等。
- DELETE：幂等；资源已不存在时返回 404 还是 204 全项目定一种；软删除后 GET 返回 404 或 410。
- HEAD、OPTIONS 交给框架自动处理；路径存在但方法不支持时返回 405，并用 Allow 头列出可用方法。
- 网关和请求层只自动重试 GET、HEAD、PUT、DELETE 和带 Idempotency-Key 的 POST，指数退避，最多 3 次。
- 文档里每个写操作标明“幂等：是 / 否 / 凭 Idempotency-Key”。

## 提示词

检查{服务名}里每个 API 的 HTTP 方法是否和实际行为一致。先读路由、控制器，以及调用方的请求层和网关重试配置。
1. 列清单：方法、路径、实际做了什么、是否改状态、按现在的实现连续调用两次会怎样。
2. 不一致的改掉：有副作用的 GET 改成 POST；整体替换用 PUT，部分更新用 PATCH；状态迁移用 POST /资源/:id/动作。
3. PUT 和 DELETE 做到真幂等：重复删除不报 500、不重复回滚库存，重复 PUT 结果不变。
4. 会被重试的 POST（{需要防重的操作}）接入「幂等键」。
5. 确认网关和请求层的自动重试只覆盖幂等请求。
6. 为“连续调用两次”写测试，断言数据库状态和只调一次相同。
最后列出改动文件，以及对调用方有影响的地方。
