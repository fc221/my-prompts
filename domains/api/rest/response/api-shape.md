## 是什么

成功响应长什么样：单个资源直接返回资源对象，列表返回 items 加分页字段，外面要不要再包一层 data。结构定死以后，前端请求层和类型生成可以一次写好。

## 适合

新服务定返回格式；老项目里有的接口包 data、有的不包，要统一；准备生成 SDK 和前端类型。

## 不适合

失败响应看「错误响应格式」；时间、金额字段的格式看「时间、金额与 ID 格式」；为某个页面裁剪、聚合数据看「前端专用后端（BFF）」。

## 注意

“HTTP 永远返回 200，body 里 code=0 表示成功”这种写法，会让网关重试、监控的失败率统计和缓存全部失灵。成功一律用 2xx，失败用 4xx / 5xx 加错误体；历史接口已经这样的，在下一个版本整体迁移，同一个版本里只保留一种。

## 要点

- 单个资源：直接返回资源对象，顶层就是 id、status、createdAt 这些字段；创建和更新返回完整资源，和 GET 的结构相同。
- 列表：顶层是对象，含 items 数组和分页字段（见「分页」），以后加汇总字段也不破坏结构。
- 团队要统一包一层时，所有成功响应都包成 data 加可选的 meta（分页、traceId），body 里不重复 HTTP 状态码；失败仍走错误结构。
- 同一资源在所有 API 里字段名一致：订单详情、订单列表项、工单里嵌的订单引用用同一套名字，列表项可以少字段，不能改名。
- 关联资源默认只给 ID 和少量展示字段，如 storeId 加一个只含 id、name 的 store 对象；完整内容用 expand 或单独 GET 获取。
- 可空字段返回 null，字段始终出现；空列表返回空数组；布尔字段用 is、has 开头（isDefault、hasInvoice）。
- 枚举值用一种写法（PAID、SHIPPED 或 paid、shipped），文档列全取值，并约定客户端遇到未知值时按“其他”显示。

## 提示词

统一{服务名}的成功响应结构。先读现有控制器的返回值、统一响应包装（如果有）、前端请求层和类型定义。
1. 列出现状：哪些 API 包了 data、哪些直接返回，列表是裸数组还是对象，有没有同一个东西不同名的字段。
2. 按这套改：单个资源直接返回对象（或团队已定的 data 包装，全部一致）；列表返回 items 加分页字段；创建和更新返回完整资源。
3. 同一资源在详情、列表、嵌套引用里字段名一致；关联资源默认只给 id 和 name，完整内容用 expand。
4. 可空字段返回 null，空列表返回空数组，枚举取值写进文档。
5. 成功一律用 2xx 状态码，body 里不再放 code=0 这类成功标记；旧接口保持原样，在新版本里迁移。
6. 更新前端类型和请求层的解包逻辑，跑一遍现有接口测试。
最后列出改动文件和对调用方有破坏的变更清单。
