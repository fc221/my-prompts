## 是什么

给调用方看的说明：从契约生成的参考文档，加上快速开始、认证说明、错误码表、示例和变更记录。目标是新接入的开发者不用问人，15 分钟内调通第一个请求。

## 适合

开放平台和合作方接入；内部多个团队共用的服务；接入方总在对接群里问同样的问题。

## 不适合

契约本身怎么维护看「契约优先」；给调用方的代码包看「SDK 与客户端生成」；接口下线怎么通知看「弃用与下线」。

## 注意

示例要真的能跑：字段值符合校验规则，金额和时间格式与线上一致，复制下来对着沙箱就能成功。示例从契约里取，并在 CI 里按 schema 校验，否则字段改了文档还是旧的。

## 要点

- 参考文档从 OpenAPI 生成（Redoc、Swagger UI、Scalar 任选），不另外手写一份；每个接口有一句话摘要和一段说明，写清用途、所需 scope、限流和是否幂等。
- 快速开始一页：申请沙箱 Key → 用 curl 调一个只读接口（GET /stores）→ 创建一笔测试订单 → 收到一次 Webhook，每步给可复制的命令和预期响应。
- 认证说明单独一页：凭证从哪里申请、放在哪个头、多久过期、Webhook 怎么验签，附签名计算的完整示例（输入、密钥、期望结果）。
- 错误码表：每个错误码写含义、常见原因、调用方该怎么做（改参数、稍后重试、联系客服），按模块分组，和代码里的错误码枚举由同一份数据生成。
- 示例：每个接口至少一组成功、一组失败示例，数据贴近业务（门店“滨江路店”、订单金额 12800 分），给 curl 和至少两种语言的写法。
- 提供沙箱环境和在线调试，沙箱数据每天重置，支付、短信等外部操作走模拟。
- 变更记录按日期倒序，每条标新增、变更、弃用或修复，破坏性变更单独标出并写迁移方法；文档可以按 API 版本切换。

## 提示词

为{服务}整理接口文档。先读现有的 OpenAPI 契约、文档站，以及接入方最常问的问题（{常见问题来源，如 工单记录、对接群}），列出缺口：哪些接口没有说明或示例、有没有统一的错误码表、有没有快速开始和沙箱、示例能不能直接跑通。
按以下规则补齐：
1. 参考文档从契约生成，每个接口写一句摘要、用途、所需 scope、限流和是否幂等。
2. 写快速开始：申请沙箱 Key、调一个只读接口、创建一条{核心资源}、接收一次 Webhook，每步可复制、带预期响应。
3. 认证页附签名计算的完整示例（输入、密钥、期望结果）。
4. 错误码表写含义、原因、处理方式，和代码里的错误码由同一份数据生成。
5. 每个接口至少一组成功和一组失败示例，在 CI 中按 schema 校验。
6. 加变更记录，破坏性变更单独标出并写迁移方法。
最后说明改了哪些文件，并按快速开始从零走一遍，记下用时和卡住的地方。
