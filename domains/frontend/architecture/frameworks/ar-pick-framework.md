## 是什么

按几条能判断的条件选前端框架和元框架：团队会什么、页面要不要被搜索引擎收录、交互有多密、需要哪些现成生态、包体积和运行环境有什么限制。目标是选团队交付最快、踩坑最少的那一个。

## 适合

新项目立项；老项目要重写或迁移；多个团队要统一技术栈。

## 不适合

框架定下来之后的目录和写法看各框架约定：「React 项目约定」「Vue 3 项目约定」「Next.js 项目约定」「Nuxt 项目约定」「SvelteKit 项目约定」「Angular 项目约定」「Astro 内容站」；页面级的渲染方式看「渲染模式选型」；小程序看「小程序与跨端」。

## 注意

团队熟练度权重最高。一个主力都会 Vue 的团队换 React，换来的“生态更大”通常抵不过头三个月的返工。下面的硬条件命中两条以上，才值得换栈。

## 要点

- 先定形态：要收录、以内容为主（官网、文档、博客）→ Astro；要收录又有大量交互（电商、社区、预约）→ Next.js 或 Nuxt；登录后的后台、工具、看板 → Vite 加 React 或 Vue 的单页应用；以微信生态为主 → 看「小程序与跨端」。
- 团队条件：主力会 Vue 选 Vue / Nuxt，会 React 选 React / Next.js；Java 或 C# 背景、需要强约定和依赖注入、多团队长期维护的企业系统可以选 Angular；小团队想要最少样板代码、能接受生态小一些可以选 SvelteKit。
- 生态条件：要大量现成的复杂组件（数据表格、甘特图、富文本、流程编辑器）或要和 React Native 共享代码 → React 生态最全；国内中后台组件库和招聘面 Vue 与 React 都够用，按团队来。
- 交互密度：页面上可交互区域不到三成 → 孤岛架构（Astro）最省；大部分区域实时变化（编辑器、协同、看板）→ 单页应用，SSR 帮助不大。
- 包体积：嵌进别人页面的小部件、首屏 JS 预算在 50KB（gzip）以内的 H5 → Svelte、Preact 或原生 Web Components。
- 部署条件：SSR / ISR 需要 Node 或边缘运行时；只有 CDN 和对象存储时选 SSG 或单页应用，或只用元框架的静态导出。
- 老项目迁移：优先同框架升级（Vue 2 → Vue 3、类组件 → 函数组件）；跨框架重写只在能按业务模块逐个替换时做，配合「微前端」或网关按路由分流。
- 结论写成一页决策记录：命中的条件、放弃的方案和原因、主要风险、什么情况下重新评估。

## 提示词

请帮{产品}做前端框架选型。先收集事实，拿不准的直接问我：
1. 团队：人数、主力熟悉的框架、TypeScript 经验、未来一年是否扩招。
2. 产品形态：哪些页面要被搜索引擎收录和分享，哪些在登录后；交互密集的页面占多少。
3. 生态：必须用到的复杂组件（表格、图表、富文本、地图），是否要和 App 或小程序共享代码。
4. 约束：首屏 JS 预算、部署环境（只有 CDN / 有 Node / 有边缘运行时）、浏览器兼容范围。
5. 现状：有没有老项目要迁移，框架和版本是什么。
然后按条件判断：内容站优先 Astro；要收录又重交互选 Next.js 或 Nuxt；后台和工具选 Vite 单页应用；团队熟练的框架优先，硬条件命中两条以上才换栈；只有静态托管时排除依赖 SSR 的方案。
输出一页决策记录：推荐组合（框架、元框架、构建工具、请求和状态库、样式方案）、命中的条件、放弃的方案和原因、主要风险、重新评估的触发条件。只写和本项目相关的判断，不写通用的框架优缺点对比。
