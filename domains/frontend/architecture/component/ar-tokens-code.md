## 是什么

把颜色、间距、圆角、字号、阴影、动效时长写成一份令牌源，生成 CSS 变量（需要时再导出 TS 常量），组件只引用令牌名、不写裸值。改主题、做暗色、对齐设计稿都只改令牌。

## 适合

代码里散落几十种十六进制色和随手写的 13px、7px；要做暗色模式或多品牌换肤；设计稿和代码对不上，每次改版都要全局搜索替换。

## 不适合

令牌的取值怎么定看「由品牌色生成色阶与语义令牌」「4/8 间距尺度」「字号阶梯」「圆角配对」「阴影层级与边框」，暗色怎么配看「暗色模式」。这条只管怎么落进代码。

## 注意

组件引用语义令牌（color-text-muted、color-bg-hover），不引用色阶（blue-500）。直接引用色阶的组件，做暗色和换肤时每一个都得改。

## 要点

- 三层：基础令牌（色阶 blue-1 到 blue-12、间距 space-1 起按 4px 递增）→ 语义令牌（surface、text-muted、border-control、accent）→ 组件令牌（只给需要单独调的组件，如 button-height-md）。组件只引用后两层。
- 源只有一份：只有 Web 时直接手写 src/styles/tokens.css；要同时给小程序、App、邮件模板用时，把令牌写成 JSON，用 Style Dictionary 这类工具生成各端文件。
- 输出：CSS 自定义属性挂在 :root，暗色用 [data-theme="dark"] 和 prefers-color-scheme 覆盖同名变量；图表、canvas 这类必须在脚本里取颜色的，从同一份源导出 TS 常量，或运行时用 getComputedStyle 读 CSS 变量。
- 命名 kebab-case，按“类别-用途-状态”：color-text-muted、color-bg-hover、radius-md、duration-fast；语义名里不出现具体颜色名。
- 用 CSS 工具类方案时，令牌写进它的主题配置并关掉默认调色板（Tailwind CSS v4 在 @theme 里定义，用 --color-*: initial 清掉默认色），方括号任意值里写色值的用法在评审和 lint 中拦下。
- 守门：stylelint 的 color-no-hex 等规则在令牌文件以外报错；内联 style 只用于运行时算出来的值（拖动位置、进度百分比）。
- 迁移：先统计所有裸值和出现次数，把近似值归并到最近的令牌（#333 和 #343434 都归到 text-primary），列映射表确认后批量替换，再截图对比。

## 提示词

把 {产品} 的样式改成引用设计令牌，界面外观保持不变：
1. 扫描样式文件和组件里的颜色、字号、间距、圆角、阴影、动效时长裸值，按出现次数统计，并找出近似值（肉眼难分的颜色、相差 1–2px 的间距）。
2. 读现有的令牌或主题配置；没有就按现状整理出基础和语义两层令牌，给出“裸值 → 令牌名”映射表，等我确认。
3. 令牌写在 {令牌文件路径}，挂在 :root，暗色用 [data-theme="dark"] 覆盖同名变量；脚本里要用的颜色从同一份源导出。
4. 批量替换，组件只引用语义令牌；加 stylelint 规则，令牌文件以外出现十六进制色就报错。
5. 对主要页面在 1440 和 390 宽下截图比对，差异只能来自近似值归并。汇报改动文件、归并了哪些值、哪些裸值因为是动态计算而保留。
