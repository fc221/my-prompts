## 是什么

决定每个页面的 HTML 在哪里、什么时候生成：浏览器里渲染（CSR）、请求时在服务端渲染（SSR，可以流式输出）、构建时生成静态页（SSG）、静态页按时间或事件重新生成（ISR / 按需重新验证）。按路由选，同一个站点里几种模式并存是常态。

## 适合

新项目定渲染方式；官网、商品详情、门店页这类要被收录的页面首屏慢或抓不到正文；后台被硬上了 SSR，部署和排错都变复杂。

## 不适合

页面里哪些部分要在浏览器里活起来看「水合与孤岛」；首屏 JS 太大看「代码分割与懒加载」；具体框架里怎么写看「Next.js 项目约定」「Nuxt 项目约定」「SvelteKit 项目约定」「Astro 内容站」。

## 注意

SSR 不等于更快：每次请求都要等数据，接口慢时首字节反而更晚，要配合流式输出和缓存。登录后才能看的页面基本不需要收录，CSR 加骨架屏通常就够。

## 要点

- 按路由判断：内容对所有人一样、以天为单位更新 → SSG；对所有人一样但几分钟一变 → ISR 或缓存加按标签重新验证；因人而异且要首屏快或要收录 → SSR；登录后的后台、编辑器、看板 → CSR。
- 要被搜索引擎和分享卡片抓取的页面，title、description、Open Graph 和正文必须在服务端返回的 HTML 里，用 curl 取源码能看到正文才算过。
- SSR 页面先输出外壳和首屏关键内容，单个超过 300ms 的慢数据单独放进 Suspense / 流式边界后补。
- 个人化内容（用户名、购物车数量、会员等级）不进静态页和共享缓存：静态页里留位置由客户端或单独的动态片段补上，SSR 响应带 Cache-Control: private 或 no-store。
- 预生成页面上千（如全部商品详情）时只预生成热门的，其余首次访问时生成并缓存，把构建时间控制住。
- 每个路由的模式在配置里显式写出（Next.js 的路由段配置和缓存声明、Nuxt 的 routeRules、SvelteKit 和 Astro 的 prerender），不靠框架默认推断。
- 先确认运行环境：SSR / ISR 需要 Node 或边缘运行时和缓存存储；只有 CDN 和对象存储时只能选 SSG 加 CSR。

## 提示词

请为{产品}梳理渲染模式。先读路由配置或页面目录，列出所有路由，每个写清：谁能访问（公开 / 登录后）、内容是否因人而异、更新频率、是否要被搜索引擎和分享卡片抓取、当前用的渲染方式。
然后按规则给每个路由定模式：公开且以天为单位更新用 SSG；公开但几分钟一变用 ISR 或缓存加按需重新验证；因人而异且要收录或首屏快用 SSR，慢数据放进流式边界；登录后的后台和工具页用 CSR 加骨架屏。个人化内容不进共享缓存。
用{框架}的方式把每个路由的模式显式写进配置或页面导出。部署环境是{部署环境}，支持不了 SSR 时给出替代方案。
完成后汇报：每个路由改前改后的模式、改了哪些文件；用 curl 取公开页面源码确认正文和 meta 在 HTML 里，看构建输出确认哪些页面被预生成。
