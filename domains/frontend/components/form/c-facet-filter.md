## 是什么

结果旁边一栏筛选项，按品类、价格、发货等分组，每项后面写当前能筛出多少条；勾一下结果立刻更新，已选条件在结果上方排成标签，可以单独去掉，也能一键清空。

## 适合

商品、模板、职位、资料库这类属性多、用户边看结果边收窄的页面。

## 不适合

后台表格按固定条件查询用「筛选区」；条件要长期复用、拼“且 / 或”时用「高级查询」；结果不到二三十条时直接列出来。

## 注意

算某一组的数量时，不计这一组自己的勾选，只计其他组。否则勾了“键盘”，“耳机”的数量就变成 0，用户以为没货。

## 要点

- 同组内是“或”，组之间是“且”；组的顺序按用户决策先后排，不按数据库字段排
- 数量随其他组的勾选实时变；数量为 0 的项置灰、位置不动，已勾的项即使变成 0 也能取消
- 每组默认露出 5–6 项，其余收进“展开 N 项”；选项上百时组内加搜索
- 已选标签的顺序跟分组顺序一致，× 的 aria-label 写“移除 键盘”；移除后焦点到下一个标签，没有就回到第一个筛选项
- “清空”只在有已选条件时出现，点后焦点回到第一个筛选项
- 结果数和各项数量由同一次请求返回，两边才对得上；请求慢时结果区淡化，并按「改了条件旧结果作废」处理晚到的响应
- 0 条结果时写“这些条件没有商品”，并给出去掉哪个条件最省事
- 分组用 fieldset + legend，结果数用 role="status" 播报
- 窄屏收进底部面板：按钮写已选数量，面板里数量实时变，底部主按钮写“看 N 件结果”
- 已选条件写进地址栏，见「筛选联动与 URL 同步」

## 提示词

给{商品列表}加分面筛选：左侧 {分组，如 品类、价格、发货} 三组复选框，宽 160px，每项右侧写数量（等宽数字）；同组内“或”、组之间“且”；算某组的数量时不计该组自己的勾选，只计其他组；数量为 0 的项置灰且位置不动，已勾的项始终可取消；每组露出 6 项，其余“展开 N 项”；勾选即更新结果，不要确定按钮；结果上方写“N 件商品”并用 role="status" 播报，下方是可单独移除的已选标签，× 的 aria-label 写“移除 {名称}”，有已选时显示“清空”；移除标签后焦点到下一个标签，没有就回第一个筛选项；0 条结果时说明并建议去掉哪个条件；窄屏收进底部面板，主按钮写“看 N 件结果”；已选条件写进 URL。
