## 是什么

用来优化数据后台的筛选、时间选择、部门标签和看板。常见症状：筛选条件铺满半屏，改一个刷一次；时间要自己算；选个部门炸出一排标签；看板满屏图表，却答不出“为什么掉了、该找谁”。数据后台的目标是帮人从几万条数据里找到下一步该做什么，这段提示词按筛选、时间、标签、看板四步整改，每步停下确认。

## 适合

已经上线的运营、客服、财务、风控后台：数据量不小，用户每天来查，总说难用又说不出哪里难用。

## 不适合

只是表格本身看不清用「优化表格可读性」；界面整体乱、要从令牌收起用「整站翻新」；从零新做列表页用「列表页（筛选 + 表格）」。

## 要点

- {三个查询任务}填真实的问题，比“优化体验”有用得多：AI 按这三件事量步数、排条件，改完也用它们验收。
- {查询耗时}填实测值，第一步靠它决定“选完即刷新”还是“点查询”。
- 第四步要用到真实口径和负责人。写不全也没关系，AI 会列出来问你。
- 只想改其中一块时，时间用「范围快捷选项」，部门标签用「树形控件」，筛选区用「筛选区」。
- 看板要的汇总或下钻维度现有接口给不了时，让 AI 列清单交给后端，先改前端能改的部分。

## 提示词

这个后台查数据很累，请按四步整改。它给{角色}用，最常查的三件事：{三个查询任务，如 昨天哪些工单超时、上周华东退款为什么涨了、某客户的合同什么时候到期}。涉及页面：{页面清单}。列表大约 {数据量} 条，查询一次约 {查询耗时} 秒。

动手前先体检，只看不改：把项目跑起来，走一遍上面三件事，列一张表，写清每件事要点几下、等几次、要不要自己算日期；每个列表页有哪些筛选条件、怎么生效、默认时间是什么。有访问日志就统计各条件的使用率，没有就问我哪些常用。表发给我，等我回复“继续”。之后每一步结束都停下等“继续”。

第一步，筛选：
1. 每页常用的 3–4 个条件放外面，其余收进“更多筛选”，按钮写已改动的数量“更多筛选（N）”，保持默认值的条件不计入。
2. 生效方式按速度定：查询 1 秒内且条件相互独立的页面，选完即刷新，加载时控件保持可操作，新请求取消旧请求，只显示最后一次的结果；超过 1 秒或常连改几个条件的页面，放“查询”按钮，改了未查询时按钮带待应用圆点，Enter 也能查询。同类页面用同一种。
3. 已生效的条件在表格上方列成可单独移除的标签，末尾“清空”；“重置”回到页面默认值，“清空”去掉全部条件，两个词别混用。
4. 条件、页码、排序写进地址栏，刷新、分享、从详情返回都保留；条件变化后回到第 1 页。
5. 空结果分两种：没有数据时给创建或导入入口；这些条件下没有时写出当前条件和“清除筛选”。

第二步，时间：
1. 所有时间筛选用同一个控件：项目组件库自带的日期范围选择器，“今天 / 近 7 天 / 近 30 天 / 本月”用它自带的快捷选项（shortcuts / presets）放进面板，不在外面另做一排按钮；默认{最常用的一档}，不留空。
2. 点完写出起止日期和天数，注明是否含今天。“近 N 天”截至昨天；“今天”写“截至 HH:mm，还没走完”；“本月”含今天。
3. 自定义范围上限 {天数} 天，超出的日期和晚于今天的日期变灰，悬停说明原因；要更长范围时引导用导出。
4. 全站按同一时区算自然日，跨时区业务在控件旁写明时区。
5. 有趋势图的页面加“和上期对比”开关：上期是等长的前一段，本月对比上月同期，今天比到同一时刻；本期实线，上期灰色虚线，并写出上期起止日期。

第三步，标签：
1. 部门、类目、地区这类树形数据改成树形多选：选整个部门收成一个标签；取消其中一个时写“客服中心 19/20”，子项不展开成标签。
2. 输入框固定一行，放不下时收成“+N”，悬停看全部；多选控件不撑高筛选区。
3. 提交的值和后端对齐：全选传部门编号，之后新建的小组自动包含；大部分选中传“部门 + 排除项”；少量选中传小组编号。接口不支持时列出来告诉我。
4. 树顶有搜索，命中时展开路径；父节点三态，键盘能上下移动、左右展开收起、空格勾选。

第四步，看板：
1. 每张看板先写一句它要回答的问题，发给我确认。答不出问题的图删掉或移到明细页，并列出删了什么。
2. 分三层：顶部一句结论（总量、较上期变化、贡献最大的一块及占比），由当前范围的数据算出；中间是原因（按{下钻维度}分的柱子，加{漏斗步骤}漏斗，恶化最多的一步标红）；下面是明细表。每块标题写成问题，如“掉在哪个渠道？”。
3. 每个数带涨跌和对比基准，比率的差值写“点”。
4. 点柱子只换范围：结论、指标、漏斗、明细同一帧切到这一块，再点取消；选中后出现“按{下一维度}拆 ›”才下钻；顶部面包屑可逐级退回，Esc 也能退；路径写进地址栏。
5. 角落写“更新于 MM-DD HH:mm”，超过正常更新周期时改成警告色。指标旁 ⓘ 就地展开口径：算什么、不算什么、统计范围。
6. 底部“下一步”：一句建议，加“导出明细”（只导当前范围）和“转给负责人”（带上当前范围）。

全程沿用现有技术栈、组件和接口，业务逻辑和数据保持原样；口径、负责人这类我没给的信息列出来问我，缺接口的列成清单写明字段，看板上只显示真实数据。每步单独提交，结尾写三行：改了哪些页面、哪件事的步数和等待次数变了、需要我决定什么。

收尾验收：用最开始那三件事重走一遍，把点击数、等待次数和体检时的表放在一起对比。
