## 是什么

用证书私钥对 PDF 内容的摘要签名，签名数据嵌在文件里。阅读器打开时能验证两件事：签名之后文件没被改过，以及是谁签的。可以带一个可见外观（印章图片、签名人和时间），也可以不可见。

## 适合

合同、报告、证明文件的签署和防篡改；系统自动给对外出具的文件加“机构签名”；多人依次会签。

## 不适合

只是想在页面上放一张印章图片，那只是图片、不是签名，看「代码直接绘制」；防止别人打开文件，看「加密与权限」。

## 注意

签名必须是最后一步。签名覆盖的是签名时整个文件的字节范围（ByteRange），签完再加水印、压缩、合并、扁平化表单都会让签名失效；签名之后只能按增量更新追加内容（比如下一个人的签名），而且要在前一个签名允许的范围内。

## 要点

- 工具：Python 用 pyHanko（MIT），支持可见签名域、RFC 3161 时间戳、PAdES B-B / B-T / B-LT / B-LTA、PKCS#11 硬件密钥，也能验签；Java 用 Apache PDFBox（Apache 2.0）；Node 有 @signpdf 系列包；iText 功能最全，但是 AGPL 或商业授权。
- 证书：对外有法律效力的签署，证书一般要由依法设立的电子认证服务机构（CA）签发，或者直接接入第三方电子签约服务；自签证书只适合内部防篡改，阅读器会显示“签名有效性未知”。
- 时间戳：每次签名都向时间戳服务（TSA）取时间戳，证明签署时间；要长期可验证（证书过期后仍能验）就用 B-LT / B-LTA，把证书链和 OCSP / CRL 应答一起嵌进文件。
- 私钥放在 HSM、云 KMS 或加密的密钥库里，签名服务只拿到“签名”这一个能力，私钥不进代码仓库、镜像和日志；每次签名记录文件摘要、签名人、证书序列号和时间。
- 多人签署：预先建好签名域；第一个签名用认证签名（DocMDP）声明后续只允许填表和签名，之后每个人的签名按增量更新追加。
- 签名之前完成所有修改：水印、表单扁平化、压缩、PDF/A 转换；需要加密的在签名之前加密，或者用支持对加密文件签名的工具。
- 验证：签完立刻用 pyHanko 验签，或用 Poppler 的 pdfsig 检查；再用常见阅读器打开签名面板，确认显示“签名后文档未被修改”。

## 提示词

给 {服务} 加一个数字签名功能：系统出具的 {文档类型}（如检测报告）生成后自动加机构签名，用 {pyHanko 或 Apache PDFBox}。
1. 先读现有生成流程；签名放在最后一步，水印、扁平化、压缩都在签名之前完成，签名后的文件不再经过任何处理。
2. 证书和私钥从 {密钥来源}（如 KMS、HSM、加密的 PKCS#12 文件）读取，私钥不落盘、不进日志；证书到期前 30 天告警。
3. 签名带 RFC 3161 时间戳（TSA 地址走配置），级别用 PAdES B-LT，把证书链和吊销信息嵌进文件；时间戳服务不可用时重试 3 次，仍失败就把任务标成失败，不输出缺时间戳的文件。
4. 在 {签名位置}（如最后一页右下角）放可见签名外观：机构名和签署时间；同时支持不可见签名。
5. 签完立即验签，不通过就判失败；记录文件 SHA-256、证书序列号和签署时间。
6. 边界情况：输入文件已有签名时追加签名，前一个签名保持有效；输入是加密文件时按 {加密文件处理策略} 处理；损坏文件直接拒绝。
