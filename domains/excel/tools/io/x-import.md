## 是什么

用户上传 Excel 批量录入（会员、商品、期初库存）时，先按表头找列，再逐行逐格校验，把所有问题一次找出来，生成一份标好错误的报告让用户改完再传；全部通过才写库。

## 适合

后台的批量导入功能；迁移旧系统数据；门店、供应商按模板定期上报。

## 不适合

数据来源是另一个系统、能走 API 或数据库同步的，就别绕道 Excel；一次性整理历史数据、不进系统的，用「用 pandas 清洗合并」。

## 注意

用户的表什么样都有：合并单元格、多余空行、前后空格、全角数字、隐藏工作表、公式算出来的 #N/A。读取时按值读（openpyxl 用 data_only=True，取 Excel 保存时缓存的结果），编码列按文本读。用户在 Excel 里把 18 位身份证号存成了数字的，后 3 位已经变成 0，程序修不回来，只能报错让用户把列改成文本后重填。

## 要点

- 提供下载模板：表头固定，录入列带下拉和数据验证；第二张“填写说明”表写每列的格式、是否必填、示例；示例不放在导入表里，免得被当成数据导进去。
- 按表头名找列，不按列位置：匹配前去掉空格、换行和全角符号，常见别名做映射（联系电话 → 手机号）；缺必填列时整表拒绝，并列出缺了哪几列。
- 逐格校验：类型（日期、金额、整数）、必填、长度、枚举（必须在下拉选项里）、格式（手机号 11 位、统一社会信用代码 18 位）、唯一性（文件内重复、库里已存在）、跨字段（结束日期不早于开始日期）；收集全部错误再返回，不在第一个错误就停。
- 日期：Excel 里的日期是序列数，1900 日期系统下 46023 是 2026-01-01，读到数字要换算；文本日期（2026.1.5、2026/01/05）统一解析，解析不了就报错，不猜。
- 数字：金额去掉千分位、“¥”和“元”后再转数值，转不了报错；整行全空的跳过，只有部分为空的按必填规则报错。
- 错误报告：在原表最后加“错误说明”列，出错的格子标红，用户改完直接再传；页面上显示“共 N 行，通过 N 行，失败 N 行”和前 20 条错误。
- 写库：先全量校验，通过后在一个事务里写入，要么全成功要么全不写；需要部分成功时，给每次导入一个批次号，可以按批次撤销。同一文件重复上传按文件哈希或业务唯一键去重。
- 限制和安全：只收 .xlsx，限制文件大小（如 10 MB）、行数（如 5 万行，超过转后台任务）和解压后的总大小（防压缩炸弹）；大文件用 openpyxl 的 read_only=True 或 ExcelJS 的 WorkbookReader 流式读；浏览器端用 SheetJS 解析时用官方 0.20.x 版本。

## 提示词

给{项目}的{资源名，如 会员}加 Excel 批量导入功能，用{库，如 openpyxl / ExcelJS / SheetJS}。
1. 先读项目里现有的上传、校验和错误返回写法，沿用它们。
2. 提供导入模板下载：列为{列定义：列名、类型、必填、规则、示例，如 门店编码（文本，必填，须在门店表里）、手机号（文本，11 位，文件内和库里都不能重复）、开卡日期（日期，不晚于今天）、储值金额（金额，大于 0）}；录入列带下拉和数据验证，另附“填写说明”表。
3. 读取：只读{工作表名}，按表头名找列（去空格、全角转半角、别名映射：{别名，如 联系电话 → 手机号}），缺必填列直接拒绝；按值读取，编码列按文本读；日期兼容序列数和常见文本写法。
4. 逐格校验上面的规则，收集全部错误，每条写明行号、列名、原值和原因。
5. 有错误时不写库，返回汇总（共 N 行、通过、失败）和一份错误报告 Excel：原表加“错误说明”列，出错格子标红。
6. 全部通过后在一个事务里写入，记录导入批次号；重复上传按{去重依据，如 手机号}识别。
7. 限制：只收 .xlsx，不超过 {大小上限} MB、{行数上限} 行，超过的转成后台任务。
8. 测试覆盖：缺列、类型错、日期为序列数、文件内重复、库里已存在、全部正确。
完成后说明改了哪些文件、怎么手动验证。
